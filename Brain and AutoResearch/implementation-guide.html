03
Phase 3 of 3
Autonomous Optimization — Autoresearch
The Karpathy Loop. An agent modifies one target file, runs your eval script, keeps improvements, discards failures, and repeats — overnight, without stopping.

No GPU required. The karpathy/autoresearch repo is for ML training. You're using the pattern — not the repo — applied to content templates, algorithms, and prompts. Claude Code is your agent.

1
Understand the three-file pattern

Every autoresearch loop has exactly three components. This is all you need to set up.

The three files
program.md     ← YOU write this: goal, constraints, loop instructions
[target file]  ← AGENT modifies this: your template, algorithm, or prompt
eval/score.js  ← LOCKED: generates outputs + scores with yes/no questions

The agent reads program.md, modifies the target file, runs eval/score.js, commits if score improved, resets if not, and loops forever.

2
Create the autoresearch folder structure

Create this folder in your a2z-webapp project (or a dedicated repo for business content).

autoresearch/ ├── smm-hooks/ ← first loop: Instagram content │ ├── program.md │ ├── results.tsv ← auto-populated, not in git │ ├── target/ │ │ └── hooks.md ← the file the agent edits │ └── eval/ │ └── score.js ← locked, agent cannot touch ├── email-subjects/ ← bridgemail templates └── supplier-matching/ ← a2z-webapp algorithm

Add results.tsv to .gitignore. This file tracks experiment scores and gets updated constantly. Don't commit it.

3
Write your first program.md (SMM hooks)

This is the human's job — writing the loop instructions. The agent reads this file and knows exactly what to do. Copy this template to autoresearch/smm-hooks/program.md.

autoresearch/smm-hooks/program.md
# Autoresearch — SMM Instagram Hooks

## Goal
Improve hook templates in target/hooks.md.
Metric: hook_score (percentage of yes answers — higher is better).

## Setup
1. Create branch: git checkout -b autoresearch/smm-hooks-[date]
2. Read target/hooks.md — this is the ONLY file you may modify.
3. Record baseline score after the first run.

## Eval
Run: node eval/score.js
Parse output: look for "hook_score: XX.XX"
Baseline is recorded on the first run.

## What you CAN change
- Hook patterns and formulas in target/hooks.md
- Variable placeholder conventions ({{brand}}, {{benefit}}, etc.)
- Pattern categories and organization structure

## What you CANNOT change
- eval/score.js — this is the locked evaluation harness
- eval/questions.json — the binary scoring criteria
- Any file outside the autoresearch/smm-hooks/ folder

## Experiment loop
LOOP FOREVER:
1. Read current hooks.md state
2. Propose ONE improvement hypothesis
3. Modify hooks.md
4. git commit with a short description
5. Run: node eval/score.js > run.log
6. Read hook_score from run.log
7. If score improved: keep the commit, advance
8. If score equal or worse: git reset --hard HEAD~1
9. Append result to results.tsv
10. DO NOT stop. DO NOT ask for confirmation. Loop until score >= 90 or interrupted.
4
Write the eval script (locked evaluation harness)

Create autoresearch/smm-hooks/eval/score.js. This is the scoring script. The agent can never modify it — it's the ground truth.

eval/score.js
import Anthropic from '@anthropic-ai/sdk';
import fs from 'fs';

const QUESTIONS = [
  "Does the hook create a pattern interrupt in the first 3 words? YES or NO only.",
  "Does it avoid starting with 'I' or the brand name? YES or NO only.",
  "Is it under 15 words? YES or NO only.",
  "Does it imply a clear benefit or transformation? YES or NO only.",
  "Is it specific enough a competitor couldn't use it unchanged? YES or NO only."
];

async function score() {
  const client = new Anthropic();
  const templates = fs.readFileSync('target/hooks.md', 'utf-8');

  // Generate 20 hooks from current templates
  const gen = await client.messages.create({
    model: 'claude-sonnet-4-20250514', max_tokens: 800,
    messages: [{ role: 'user', content:
      `Using these templates:\n${templates}\n\nGenerate 20 Instagram hooks. One per line.` }]
  });

  const hooks = gen.content[0].text.split('\n').filter(h => h.trim()).slice(0, 20);
  let yes = 0, total = hooks.length * QUESTIONS.length;

  for (const hook of hooks) {
    for (const q of QUESTIONS) {
      const r = await client.messages.create({
        model: 'claude-sonnet-4-20250514', max_tokens: 5,
        messages: [{ role: 'user', content: `Hook: "${hook}"\n\n${q}` }]
      });
      if (r.content[0].text.trim().startsWith('YES')) yes++;
    }
  }

  const score = ((yes / total) * 100).toFixed(2);
  console.log(`hook_score: ${score}`);
}

score();

Daily usage workflow

What a typical day looks like once all three phases are running.

Morning
Start your session
  • Open Claude Code — session start hook auto-injects yesterday's compiled knowledge index
  • Run claude --continue to resume from where last session ended
  • If autoresearch ran overnight: git log autoresearch/[target] --oneline and check results.tsv
  • If results are good: git merge the improvements into main
During work
Code and build normally
  • Code as normal — memory compiler captures everything silently in the background
  • When you find a useful article: click Web Clipper → save to raw/articles/
  • When completing a major feature: run /handover to create an explicit snapshot
  • To ingest a new article: open Claude Code in vault root, say ingest raw/articles/[file].md
Evening
Launch an autoresearch loop (optional)
  • Pick one optimization target for tonight (hooks, subjects, algorithm, etc.)
  • Open Claude Code, say: "Read autoresearch/[target]/program.md and start the loop. Do not stop."
  • Leave Claude Code running. Go to sleep. Agent runs 50–100 experiments overnight.
  • Morning: check results, merge if good
Weekly
Maintenance (15 minutes)
  • Run uv run python scripts/lint.py — knowledge base health check
  • Batch-ingest any articles saved during the week into the Obsidian vault
  • Git sync both machines: git add . && git commit -m "weekly sync" && git push
  • Review top knowledge base entries — anything to update or correct?
